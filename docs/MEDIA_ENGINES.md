# 图片引擎升级与历史复算

最新安装图已改为官方模块 @ganache/core 0.10.2，同主版本安全补丁和旧链兼容5组通过；当前生产/完整依赖扫描严重0、高危0、中危0、低危35。该扫描不覆盖这里单独封存的历史原生引擎，原生库风险及隔离边界仍保留。见[最新高优先级记录](HIGH_PRIORITY_2026-10-25.md)，下文为历史过程。

2026-10-25后续：OpenZeppelin已找到兼容Shanghai的5.4.0并完成真实链验收，现已发布；此前5.6.1失败尝试仍未采用。tmp定向固定0.2.7，本地生产扫描现为33项Ganache相关告警。下文36项及保留5.2.0为上一轮历史状态，最新见[后续记录](REMEDIATION_2026-10-25.md)。

2026-10-25：当前依赖固定为 sharp 0.35.5、solc 0.8.38。OpenZeppelin 保持 5.2.0；试验 5.6.1 时实际 Shanghai 合约编译因 MCOPY 失败，未采用该升级，也没有迁移既有合约。

声明的 engineDigest 绑定完整图片库版本信息。升级不能把旧摘要当作新引擎，也不能用“当前输出看起来相同”替代历史复算。

升级前，在原平台和旧依赖仍可运行时执行：

```text
node scripts/archive-media-engine.mjs /受控路径/media-engines
```

工具将旧工作进程打包为独立 CJS 文件，复制其原生依赖，记录逐文件 SHA-256 和目录清单，并生成固定描述文件摘要的 catalog.json。没有开发编译器的主机可把第三个参数设为预先审核并校验过的旧 worker.cjs；该文件只由运维提供，不能来自上传的证据 ZIP。归档需与平台和架构一致，不能把 Windows 原生库部署到 Linux。

在服务或独立验证器环境中显式配置：

```text
CP_MEDIA_ENGINES_FILE=/受控路径/media-engines/catalog.json
```

目录和目录的上层应由运维管理，应用用户只读。上传的证据不能设置此环境变量。运行前核对描述文件摘要、引擎摘要、平台、架构、全部文件摘要以及未列入的文件；拒绝目录逃逸、链接和超出大小限制的归档。旧工作进程沿用限时、队列和内存约束，旧原生库的风险仍存在；子进程并不等于完整操作系统沙箱。

无匹配引擎、损坏归档或工作进程不可用时，返回“无法复算”，不宣称验证通过。正常执行但字节摘要不同则返回“不匹配”。

本轮用旧引擎创建了含 PNG/JPEG、裁剪、缩放、旋转、合成的真实六节点签名图，升级后通过归档复算。此专用用例的链观察是显式测试替身；真实链业务检查另有独立报告，不能将两类证据混为同一项验收。证据位于 data/dependency-upgrade-2026-10-25。

本地生产依赖扫描仍有 36 项告警（5 critical、24 high、6 moderate、1 low），不是清零；其中包含 Ganache 捆绑组件。完整许可原文仍有 4 项缺口。历史依赖归档不属于当前 npm 安装树，不能用根目录扫描结果代表历史归档已无风险。

另外修正了 Ganache 锁文件中 fsevents@2.3.2 缺少 optional 标记的问题。其父组件 chokidar 将它声明为 macOS 可选依赖；修正保留既有版本、来源和完整性摘要，使 Linux npm ci 可以按平台跳过它，不使用强制安装绕过平台检查。
