# 本地数据保留与归档

`data/` 被Git忽略，里面的备份、安装器、原生工具、业务数据和测试快照不受仓库版本管理保护。源码推送不能替代数据备份。

2026-10-26只读盘点约17.0GiB，其中docker-recovery约14.43GiB、tools约1.43GiB、soak-artifacts约0.66GiB、cloud-delivery约0.15GiB。数量是观测快照；运行 `npm run data:inventory` 可重新生成只含目录级元数据的清单，不读取文件内容，也不跟随链接或删除文件。

| 目录 | 保留和归档规则 |
|---|---|
| docker-recovery | 冷备份与恢复安装器人工归档；必须有独立副本、摘要核对和恢复验证后，才能决定清理本机副本。没有第二份已验证副本时继续保留。 |
| tools | 保留当前pin版本及一个已验证回退版本；30天后审阅多余安装器和过期工具。先核对配置与调用路径，避免破坏原生验证。 |
| soak-artifacts | 活动轮次和未查清失败不清理；已完成合成数据30天后审阅，至少保留7轮完整记录及摘要。原始失败证据不得改写。 |
| cloud-delivery | 超过7天的旧包进入人工审阅；保留当前已验收包和至少两个回滚包。活动冻结测试使用的源材料继续保留。 |
| 业务库、身份、密钥、云接入目录 | 逐项人工管理，不套用合成测试数据的保留期。加密备份与解密材料分别控制访问。 |

机器可读规则在 `configs/data-retention.json`，模式为 `inventory-only`。期限表示审阅时间，不代表届时自动删除。本次未删除、移动或压缩现有数据，也没有减少这17GiB占用。

要移出项目目录，应先指定独立存储位置，停止可能写入的相关任务，制作清单与摘要，复制并核对，验证工具/恢复路径后再决定本机副本去留。仅移到同一磁盘的另一个文件夹不能提供异机灾备。
