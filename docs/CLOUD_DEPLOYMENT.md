## 已部署内容

- 预先构建的网页、编译API/独立验证器、Node 22.23.4及Linux生产依赖；服务器不现场编译。
- `contentproof.service`以独立的contentproof系统用户运行，开机自启，运行数据在 `/var/lib/contentproof/app`。程序使用版本目录及current链接，与运行数据分开。
- API和参考链仅监听127.0.0.1，Nginx提供80/443入口。AUTH_AUDIENCE与允许的浏览器来源对应实际HTTPS地址，demo关闭。
- 图片并发1、队列4、Node堆256MiB；整个应用服务内存上限1200MiB，另配置2GiB交换空间。低内存设置不代表任意负载都不会耗尽资源。
- 官方固定版本C2PA 0.28.2原生程序，启动时再次校验二进制及运行能力。实际Ubuntu24.04中已验证可运行；未配置CA策略时不自动信任嵌入证书。
- 每日停止应用及其本地链后生成加密备份，再恢复服务。存储密钥与备份口令在服务器受控目录，生成时不输出；不会复制本机开发数据或开发私钥。
- 每分钟检查本机就绪接口，连续失败后在维护锁保护下重启服务；显式停机和429繁忙状态不会触发重启。这是单机恢复辅助，不等于高可用。

## 关键文件

| 文件 | 用途 |
|---|---|
| `scripts/package-cloud.ts` | 收集已编译程序及公开源码，排除运行目录和密钥 |
| `deploy/cloud/build-runtime.mjs` | 在 `/validation/node_modules` 已按锁文件准备的Linux容器中，仅保留生产依赖，装入Node与固定哈希的C2PA程序，生成逐文件摘要及运行归档 |
| `deploy/cloud/provision.sh` | 校验归档及文件摘要，安装独立服务、持久化目录、资源限制与备份定时任务；首次仅开放HTTP证书验证路径 |
| `deploy/cloud/enable-https.sh` | 经运营者同意证书协议后，测试及正式签发IP证书、配置HTTPS和自动续期 |
| `deploy/cloud/contentproof.service` | 应用及参考链的启动配置 |
| `deploy/cloud/backup.sh` | 停机一致性加密备份，结束时恢复此前运行的服务 |
| `deploy/cloud/*certificate*` | 每六小时检查短期IP证书续期 |

构建前运行 `npm run build`，再运行 `node --import tsx scripts/package-cloud.ts`。运行包准备工具需要容器中的 `/tmp/source.zip` 和校验固定版本的 `/tmp/c2patool.tar.gz`；生产依赖必须从Linux环境准备，不能使用Windows的node_modules。运行包在data内，不等同于仅含公开代码和选定报告的源码发布ZIP。

`provision.sh`参数依次为上传归档的绝对路径、SHA256和公网IPv4。它需要root安装权限、已安装的Nginx/openssl等基础组件；选择新的版本目录，不覆盖已有同名版本。`enable-https.sh`使用ecs-user部署账号的上传目录接收证书服务和timer配置。管理员需核对云安全组80/443入方向规则，其他服务按实际需要管理。

2026-10-25起，升级保留已有app.env及Nginx/HTTPS配置，不重新开放被关闭的注册，也不清空审核人或密钥/RPC设置。旧配置没有TRUSTED_PROXIES时，只补充固定本机代理127.0.0.1/32；显式已有值会保留。当前内置代理要求应用仍监听127.0.0.1:3001，其他端口/监听方式会要求先核对配套代理。更换公网IP或域名需要明确修改来源/证书配置，升级脚本不会自动替换原有信任设置。首次配置仍须运营者设置OPERATOR_ADDRESSES完成机构审核人的登记。

## HTTPS及费用

本次使用公网IP访问，没有购买域名。Let's Encrypt支持IP证书，需要选择shortlived配置，证书有效期约160小时；已配置定时续期和Nginx重载，并完成实际续期模拟。签发前需由运营者确认当期订户协议，IP将进入公开证书记录。

证书免费，云服务器仍按原套餐或按量规则计费。公网IP改变后，需重新配置访问来源和证书；换成域名时也需调整配置和浏览器身份备份/迁移。

参考：[Let's Encrypt IP证书说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot.html)、[阿里云系统更换说明](https://help.aliyun.com/zh/ecs/user-guide/replace-the-operating-system-of-an-instance)。

已完成8项非demo业务检查，包括合成图片上传、客户端签名、登记、派生编辑、导出、独立验证及撤回；完整停止/重启后4项持久化检查通过。加密备份已生成，并恢复到独立目录检查数据库完整性、外键和密钥。公网HTTPS再完成9项实际业务检查，覆盖正常CA验证、来源拒绝、登录、上传、签名登记、派生编辑、导出复算、原生验证器状态和退出。本轮还检查了Ubuntu上的原生C2PA、单任务资源配置及HTTP跳转。

本机恢复口令与加密备份的复制曾被自动审批拒绝，之后取得用户对具体本机受保护目录的明确授权才执行。私钥和恢复口令不进入源码发布包，报告不包含这些值。

首次访问应由用户本人创建身份、设置口令并保存加密身份备份。浏览器身份私钥不由服务器生成或保管。新HTTPS来源和本机localhost属于不同浏览器存储空间；迁移已有身份应使用加密身份备份。
