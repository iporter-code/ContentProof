# 威胁模型与限制

攻击者可改媒体/证据包/数据库，提交恶意ZIP、重放旧签名、用其他密钥冒充或尝试跨机构读文件。安全前提为SHA256/ECDSA安全、密钥和本机执行环境未泄露、可信部署配置正确、链和RPC符合配置的信任模型。

防护分别是精确字节摘要、字段/有序父承诺、EIP712域+合约nonce/deadline、授权密钥、链上只追加记录、独立重新验证、组织ACL、会话挑战、私有数据AES-GCM、输入/解压大小限制。数据库索引是加速缓存而非证据。开发模式仅监听loopback，跨Origin访问被拒绝。

撤销泄露密钥对历史签署采用保守拒绝；正常停用保留历史签署可核验性。撤回不删除历史承诺。离线无法保证最新撤销状态，报告必须保留unchecked/offline。

不能保证：画面真实性、权利归属、原始采集可信、没有隐含素材、AI标签客观正确、链下数据永存、隐藏字段对所有侧信道不可推断、单机链抗管理员作恶。媒体隐藏可能被公开派生图部分重建；结构、签署地址、大小、计数和操作公开。若同一隐藏素材由另一公开路径引用，仍会出现。

本轮已实现用户自持密钥UI、默认关闭演示接口、新素材认证加密、原owner授权撤销、持久化单机节点和脱敏操作日志。用户名称仍为自述，不能等同机构认证。管理员控制本机链和费用账户，单机持久化不抵抗管理员重写历史。

已实现限定范围的同机多节点、可信RPC故障切换、资源限制、备份恢复、密钥轮换及本机告警；它们不等于独立机构生产部署或完整安全评估。外部钱包实机、复杂网络/恶意节点、异机灾备和生产Vault/KMS仍有验收缺口。默认Ganache依赖已归档，生产依赖风险尚待维护节点迁移及调用可达性分析，不能因测试通过就标记为全部消除。

浏览器签署的信任前提包括前端代码来源和浏览器本机可信。客户端从本地草稿重算字段/有序父承诺，比对文件、参数、issuer、epoch及已确认网络，阻止API在prepare阶段替换签署内容。首次网络确认仍须由用户与部署方核对；前端代码本身被替换不在这项防护的保证范围内。恢复旧数据必须提供原密钥，程序不会通过生成新密钥修复丢失的历史密钥。
